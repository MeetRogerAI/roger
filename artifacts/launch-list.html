How this list is used

  1. Claude Code reads it before starting any version of the build.
  2. If an item that blocks that version is still open, Claude Code stops and asks Peter. It does not make the content up. Where a row names a fallback, the build goes ahead with the fallback.
  3. When Peter supplies an item, Claude Code checks it against "Done when", marks the row done with the date, and notes where it now lives.
  4. Every default is built as written. When Peter confirms or changes one, Claude Code records it here and, if it changed, updates the spec and the code together.
